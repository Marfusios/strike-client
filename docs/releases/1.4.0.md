Expanded the client to cover all 49 operations in Strike's published API reference, audited on September 24, 2026.

- Added account limits, invoice cancellation, events, webhook subscriptions, payouts, and payout originators.
- Added invoice transaction details and the documented invoice sorting and transaction query options.
- Updated existing models for current balances, payment details, travel-rule beneficiaries, nullable fields, and AUD currency support.
- Added 64-bit pagination totals and `IsCountUnknown`. Existing `int Count` properties remain available; use `TotalCount` for values above `Int32.MaxValue`.
- Corrected JSON field names, date-only birth dates, idempotency metadata, URL encoding, and repeated array query keys. API exceptions now retain structured error details.
- Removed request bodies from trace logging so webhook signing secrets are not logged.
- Preserved existing public signatures and .NET Core 3.1, .NET 6, .NET 8, and .NET 10 targets. Legacy methods absent from the current reference remain available.
- Added offline contract coverage for the new and corrected APIs. Live integration tests remain protected against requests that write or spend funds.
- Added automatic GitHub release notes after successful NuGet publication; CI requires a notes file for each version and verifies the published package's commit before tagging.

Validation: zero-warning Debug and Release builds; 238 offline tests and 22 read-only live checks passed. API compatibility passed against 1.3.2 on all four library targets; packaged consumer smoke tests passed on .NET Core 3.1 and .NET 5 through 10. The live account-limits check is skipped when its required `partner.account.profile.read-own` permission is unavailable. No spending requests were sent.

See the [API coverage audit](https://github.com/Marfusios/strike-client/blob/v1.4.0/docs/api-coverage.md) for endpoint mappings and compatibility notes.
